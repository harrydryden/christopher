# CV build recovery and progress — 13 September 2026

The repeated three-page error had a production cause: the Render worker was still running `e145570` from 11 September. The web application had the newer PDF renderer and download constraints, while the worker still generated content without the measured fitting or assessment pipeline. Render reported auto-deploy enabled, but its live release and recent deployment history showed none of the later CV changes. Deploying merged commit `da6aa3d` restored the fitting and assessment pipeline in production.

There were also two recovery gaps. Saving an oversized edit failed before it could reach the fitter. Assessment-only jobs accepted oversized legacy content and scored it without fitting. Saving now queues the wording; the worker measures it, fits overflow using the saved appearance, and only assesses the resulting PDF text. A final measured page-count assertion prevents any new ready draft exceeding two pages. Valid two-page edits keep the existing assessment-only path. Employment and qualifications remain protected; impossible layouts still fail without clipping or reducing font sizes.

The draft page now puts appearance, fitting, improvement and saving controls first. The company's exact saved description appears beside the editor with independent scrolling, minimise and hide/reopen controls. Closing the panel preserves unsaved state. On narrow screens the description stacks below the editor. PDF previews remain available for oversized legacy drafts and recoverable assessment failures; final downloads and application records retain their finalisation checks.

Build stages are stored with the draft: analysing, writing, fitting and assessing. Polling notices stage changes, not just queued/ready transitions. Its initial version comes from the rendered page, fixing a race where changes before the first poll could otherwise be missed. The wheel animation accompanies the actual stage; there are no timer-based percentage estimates. Reduced-motion mode uses the monochrome mark. A single additive migration, `0016_cv_build_progress.sql`, adds the nullable stage field. Retries clear stale stages and ready drafts clear progress.

Verification covers saved oversized content, preservation of edited appearance, scoring only fitted wording, stage reporting, full PDF rendering, and existing finalisation/application safeguards. The production web smoke check now exercises a real browser against synthetic drafts: appearance settings, hide/reopen and minimise controls, preservation and submission of edits, mobile overflow, reduced motion, queued revision creation, and polling through assessment to completion. No model calls are made by that browser check.

## Release verification

A merge alone does not prove either service has updated. For CV releases, verify the Vercel web deployment and the Render worker deployment against the intended commit; trigger the worker deployment if it is behind. The worker now includes its Render commit in its health response and heartbeat, and the Health page displays it. This makes the running release inspectable rather than inferred from GitHub or the auto-deploy setting. The main-branch CI release check now waits for that exact commit at the worker health endpoint and fails if the deployment stays behind; no deployment credentials are needed for this check. Check migration/start-up logs after deployment and inspect a newly generated or refitted draft, including its assessment and measured page count. Existing submitted application PDF bytes must remain unchanged.
