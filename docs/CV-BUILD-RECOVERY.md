## Release verification

A merge alone does not prove either service has updated. For CV releases, verify the Vercel web deployment and the Render worker deployment against the intended commit; trigger the worker deployment if it is behind. The worker now includes its Render commit in its health response and heartbeat, and the Health page displays it. This makes the running release inspectable rather than inferred from GitHub or the auto-deploy setting. The main-branch CI release check now waits for that exact commit at the worker health endpoint and fails if the deployment stays behind; no deployment credentials are needed for this check. Check migration/start-up logs after deployment and inspect a newly generated or refitted draft, including its assessment and measured page count. Existing submitted application PDF bytes must remain unchanged.
