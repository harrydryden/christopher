# Add a role from a link or PDF

From **Roles → Add role**, a verified account can submit one HTTPS job advert or upload a text PDF. The worker extracts a private, unconfirmed description. The person checks or edits the title, employer, location and full description before **Save role** creates a private `jobs` row and its `user_jobs` view, then shortlists it. **Build CV** uses the existing CV pipeline. If role analysis raises factual gaps, the build pauses at the evidence quiz; answering or explicitly skipping that quiz is required before writing continues.

Manual roles belong to `jobs.manual_owner_id` and use `origin = 'manual'`, `shared = false`, an employer label and an account-scoped fingerprint. They need no company subscription or career source and never enter another account's shared catalogue. A PDF has no vacancy URL or fabricated employer website. Repeated input for one account reuses the existing import or role; another account's matching input remains separate. The import row is also account-scoped, and the worker checks its owner and queue lease before publishing results.

The web action accepts HTTPS links of at most 2,048 characters and PDF uploads of at most 5 MB. The worker fetches links with the existing public-address, redirect, robots and bot-challenge guards, with a 3 MB response cap. PDF bytes go through the bounded document parser: at most 5 MB compressed input, guarded expansion and PDF content limits, and 40,000 extracted characters. An extraction that would be truncated is refused instead of silently producing a partial advert. A confirmed description may be 80–60,000 characters; this larger ceiling also supports text the person pastes during recovery or review. Uploaded bytes are cleared on successful extraction and retained on a readable failure so the person can retry or replace the PDF. Failed and exhausted tasks surface a retry or manual paste path; no paid AI call is used to ingest the description.

Migration `0054_manual_role_imports` must be applied before the new web action runs. Deploy the web producer and the worker that handles `import_role_description` together, so submitted imports have a consumer. Existing scanned postings retain their company and source requirements through the migration's check constraint.

Verification covers account isolation, link and PDF extraction, blocked pages, unreadable PDF recovery, existing posting imports, and a manual role entering the CV quiz and continuing after it. Browser verification used a controlled extraction fixture. A separate local run passed a real five-page text PDF through the import handler without truncation and cleared its temporary bytes. No paid live model CV build or live external job site was used in this verification.
