Two defects were discovered and corrected in source after the frozen run:

- Settings had separate Keywords and Location saves. A location-only first save created a `gate` row from the default `operations` keyword, marked setup preferences complete, and could admit unrelated roles. The initial Settings view now uses one combined form, and the server rejects partial first saves, including Match fields and filter-suggestion acceptance. Subsequent independent edits merge only submitted fields under the same account lock used by suggestion acceptance, so concurrent tabs cannot replace each other's keyword or location changes. The corrected build was browser-checked with a second fresh confirmed account: blank Save filters showed “Enter at least one keyword”, focused the alert and wrote no gate; one Save filters with Engineer + United States wrote precisely those choices and advanced setup from 1/4 to 2/4. The second account remained at zero follows/roles, despite the shared catalogue containing Render jobs, confirming account isolation. Existing gate rows created by the old location-only path cannot be distinguished from deliberately saved `operations` filters and are not rewritten automatically. [Setup after the combined save](implementation-evidence/first-use-live/setup-combined-saved.png).
- With AI disabled, the worker wrote `score_state=budget` even though `ai_calls=0` and each task result said `ai unavailable`. All 17 rows misleadingly showed “not scored: budget spent”. The worker now records a distinct `unavailable` state for no-model scoring, and Roles says “AI scoring unavailable; review manually” beside its Review action. Both live and batch preparation paths use this guard. Historic `budget` rows remain ambiguous; this fix applies to new scoring work, and the corrected text was tested in the web formatter and worker database tests. A paid provider was never enabled here, so model scoring quality is untested.

This failure remains part of the evidence; the next run tested the correction from a new empty database.
