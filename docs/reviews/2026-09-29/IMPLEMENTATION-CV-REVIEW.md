## What changed and what is demonstrated

- J1's setup decision is derived from account-scoped subscription and source facts, not a blank role table: `apps/web/lib/queries/setup.ts:45–107`, `apps/web/lib/setup.ts:57–79`, `apps/web/components/SetupChecklist.tsx:5–34`. The query's integration test covers another account's successful source, queued discovery, partial scan, complete zero-posting scan and unusable Library evidence (`apps/web/lib/queries/setup.test.ts:153–179`). The mobile shell has a single collapsible navigation tree, a skip link and direct Health/Learning entries (`apps/web/components/WorkspaceMenu.tsx`, `apps/web/app/(app)/layout.tsx:47–84`). The parent reported a 390px Roles browser check with no page overflow and first role at y=546; I have not independently reproduced that browser observation.
- J4's new summary names the current build/review/finalise step and links to the relevant workspace tab or final PDF (`apps/web/lib/cv-next-action.ts`, `apps/web/components/CvNextAction.tsx:5–13`, `apps/web/components/CvWorkspace.tsx:91–119`). Pure and component checks cover the state mapping, destinations and tab transition (`apps/web/lib/cv-next-action.test.ts`, `apps/web/components/CvWorkspace.test.tsx`). Existing finalisation still checks assessment freshness, claims and page limits; this work did not relax those gates. The summary simplifies orientation but does not replace a first-time user walkthrough.
- J5's three-way merge preserves the exact original local draft, names each competing value and asks which to keep. It also makes a local deletion an explicit conflict and rejects a choice that would leave evidence pointing at a removed job (`apps/web/lib/cv-library-merge.ts:66–205`, `apps/web/components/CvLibraryEditor.tsx:216–257,364–386`). Copy, download and read-only JSON remain available even for an invalid merge; the invalid-case escape explicitly restores the latest saved version after confirmation (`CvLibraryEditor.tsx:260–281,386`). A stale-save component interaction checks the original text and choice controls, while pure tests cover ordinary, deletion and invalid combinations (`apps/web/lib/cv-library-editor.test.ts`, `apps/web/lib/cv-library-merge.test.ts`). These are local checks, not a two-tab browser run; browser refresh before copying still relies on the existing unsaved-changes prompt, not persisted draft storage.
- J5's import post-check anchors a current role to a year-to-Present/current/ongoing date span and refuses a model-supplied `current: true` where the heading carries an end date; a job title containing “Current” is not enough (`packages/core/src/library-import.ts:348–356`, `packages/core/src/library-import.test.ts:180–216`). The import card becomes actionable at 15 minutes on its own browser clock, including when the polling signature does not move (`apps/web/components/LibraryImportReading.tsx:7–34`, `LibraryImportReading.test.tsx`). Retrying an old import resets that attempt's deadline (`apps/web/lib/queries/library-imports.ts:76–84`), covered by the import action integration test. Employment and responsibility editing have a single control per field at phone and desktop widths (`apps/web/components/EmploymentHistoryTable.tsx:45–76`, `apps/web/components/CvLibraryEditor.tsx:454–505`); static markup checks catch duplicate controls but do not prove 320px usability or keyboard behaviour with a software keyboard.
- J8 benefits from those recovery changes and from the separate discovery workstream's suspect-scan and stale-discovery fixes. I reviewed setup's account scoping and its distinction between partial and complete company success. The full cross-surface failure matrix and hosted retry behaviour remain to be verified in the parent task.

## Gates that still constrain a 90/100 claim

1. **Current provider evidence:** the committed CV replay report at the shipped prompts is explicitly an unverified scripted fixture (`docs/evaluations/cv-replay/report.json`). The executed 20 September provider comparisons are historical and broader; they do not verify this worktree's current prompts or real applicant quality. Run representative paid-provider CV, Library review and import cases with independent claim/chronology and PDF review, including sparse and adversarial documents, before increasing J4/J5 robustness or claiming hiring value.
2. **Ordinary and recovery browser journeys:** finish a two-tab Library collision with copy/download, both conflict choices, invalid merge, local deletion and navigation/reload; repeat at 320px and 390px with long evidence and 200% text zoom. Complete build → correction → reassessment → preview → finalise → download and optional comment loop. Check keyboard and assistive-technology announcements. These gates affect J4/J5/J8 UX and robustness.
3. **First-value and exception matrix:** run fresh-account preferences → company → complete zero-match scan, queued/failed/suspect/partial source, retry, and role result on actual browser screens. Ensure every state presents one truthful explanation and reachable action, and that the empty state never infers that nothing has run from an empty table. This affects J1/J8.
4. **Pricing and release qualification:** the replacement-advert quote was still being improved by the Applications owner during this review; do not score it as verified until visible price and action admission agree for the actual pasted text. Record the parent task's exact-build/full-suite result before changing these provisional scores. Hosted recovery and delivered alert evidence belong to J9 and cannot be inferred from local tests.
