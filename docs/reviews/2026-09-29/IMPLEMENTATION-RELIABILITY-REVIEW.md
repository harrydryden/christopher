# Reliability and role-review implementation, 29 September 2026

This is a working-tree review of the changes on `codex/jtbd-90`. The 29 September baseline remains historical evidence. Local implementation and scripted tests do not pass the independently labelled discovery, live provider, hosted-capacity or release gates.

## What changed

- Health now treats the latest **completed, non-failed** scan per active source as the relevant result. A `partial` or `suspect_empty` scan raises an actionable item in both the list and sidebar count; a later failed request does not erase it, and a subsequent complete `ok` scan clears it ([query](</Users/h_dryden/Documents/New project/christopher-jtbd-review/apps/web/lib/queries/health.ts:1340>), [count](</Users/h_dryden/Documents/New project/christopher-jtbd-review/apps/web/lib/queries/health.ts:1423>), [controls](</Users/h_dryden/Documents/New project/christopher-jtbd-review/apps/web/components/HealthItems.tsx>)). The scan statuses in that query are terminal outcomes, so an in-progress scan cannot clear attention.
- Suggestion acceptance now reads, merges and saves the current gate while holding the account settings lock, then settles the suggestion in the same transaction. Rejection only changes a pending suggestion. This prevents two accepted terms from overwriting each other ([action](</Users/h_dryden/Documents/New project/christopher-jtbd-review/apps/web/app/actions/learning.ts:138>), [locked writer](</Users/h_dryden/Documents/New project/christopher-jtbd-review/apps/web/lib/settings.ts:78>)).
- Discovery checks the company's current homepage under a row lock before saving a source. An administrator's homepage correction also queues a fresh discovery, while an old in-flight result finishes as stale rather than attaching the old page ([worker](</Users/h_dryden/Documents/New project/christopher-jtbd-review/apps/worker/src/handlers/discover.ts:132>), [action](</Users/h_dryden/Documents/New project/christopher-jtbd-review/apps/web/app/actions/admin.ts:54>)).
- Roles now have a single semantic table whose existing rows become mobile cards through scoped CSS; there is no second interactive role list. The filter bar collapses its fields behind one phone toggle, names **Update results**, shows an active-filter summary, and preserves company scope on **Clear filters** ([table](</Users/h_dryden/Documents/New project/christopher-jtbd-review/apps/web/components/RolesTable.tsx:260>), [card CSS](</Users/h_dryden/Documents/New project/christopher-jtbd-review/apps/web/components/RolesTable.module.css:1>), [filters](</Users/h_dryden/Documents/New project/christopher-jtbd-review/apps/web/components/RolesFilterBar.tsx:42>)). The client filter options were extracted from the database-backed query module so the production bundle remains browser-safe ([options](</Users/h_dryden/Documents/New project/christopher-jtbd-review/apps/web/lib/roles-filter-options.ts>)).

## Undo semantics

The most recent five successful shortlist/dismiss decisions remain available in account-scoped `sessionStorage` across filter and page remounts. A decision in flight has an immediate Undo; Undo waits for its save and does nothing if that save was refused. Failed Undo leaves its history entry and displays the server's reason, including when the table is empty ([history](</Users/h_dryden/Documents/New project/christopher-jtbd-review/apps/web/components/role-undo-history.ts>), [table](</Users/h_dryden/Documents/New project/christopher-jtbd-review/apps/web/components/RolesTable.tsx:756>), [scope](</Users/h_dryden/Documents/New project/christopher-jtbd-review/apps/web/components/RoleWorkspace.tsx:86>)).

The save actions return each new standing decision's ID. Single Undo, panel Reset and bulk Undo submit exact IDs; the server locks the account's role rows in sorted order and reverses only if every ID is still standing. One stale item rejects the whole bulk operation, retaining the selection and its error. Thus an older tab cannot undo a newer tab's call ([single and conditional actions](</Users/h_dryden/Documents/New project/christopher-jtbd-review/apps/web/app/actions/decisions.ts:137>), [bulk actions](</Users/h_dryden/Documents/New project/christopher-jtbd-review/apps/web/app/actions/decisions.ts:267>), [writer](</Users/h_dryden/Documents/New project/christopher-jtbd-review/apps/web/lib/decisions.ts:111>)). Older tokenless browser history is excluded and offers **Reload roles**; it is never sent as an unguarded Undo. Newer same-tab decisions also invalidate older entries. The existing `decide` and `decideRoles` response shapes remain unchanged for other callers.

Replay intentionally does **not** renew its operation lease: it runs in a rollback-only transaction, so renewal is skipped; active lease renewal has separate coverage in `scaling.test.ts`. This repairs a brittle test signal, not a product failure.
