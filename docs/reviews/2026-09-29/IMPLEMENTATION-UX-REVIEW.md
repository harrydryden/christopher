## Implemented and locally demonstrated

**J2 — watching and recovery.** Health now retains a suspect-empty or partial listing as an actionable company item until a later complete scan or source resolution; the list and count use the same state rule (`apps/web/lib/queries/health.ts:1329–1370,1406–1437`). Discovery compares the homepage it fetched with the current one before persisting, so an old in-flight result cannot attach its source after an administrator changes that homepage (`apps/worker/src/handlers/discover.ts:123–211`). The Companies page presents company, source and management together on a phone, and Discover accepts up to 25 homepages with per-item results (`apps/web/app/(app)/companies/page.tsx`, `apps/web/app/(app)/suggestions/page.tsx`, `apps/web/app/actions/companies.ts`). Dedicated Health/learning, catalogue-action and worker discovery/fetcher/replay suites passed in the reliability workstream; this review has not rerun a live careers crawl. The parent has a 25-company no-AI browser-source diagnostic in progress. That diagnostic will inform current behaviour but cannot alone replace the SPEC's independently labelled source and posting-identity acceptance set.

**J3 — rapid decisions.** The Roles worktree has responsive role items, a clearer filter bar and visible active filters (`apps/web/components/RolesTable.tsx`, `apps/web/components/RolesFilterBar.tsx`, `apps/web/components/RolesTable.module.css`). The phone shell reduces navigation depth (`apps/web/components/WorkspaceMenu.tsx`, `apps/web/app/(app)/layout.tsx`). The parent measured the first role at about y=546 on a 390px browser view rather than below the initial screen; that is a reported browser observation, not a fresh observation in this note. The decision action and conditional undo are under final reliability testing (`apps/web/app/actions/decisions.ts`, `apps/web/components/role-undo-history.ts`). Keep robustness at 4 until the final race regression and ten-role browser journey pass.

**J6 — truthful progress and a usable queue.** The global pipeline index records the latest live next-step due date, filters and sorts *before* pagination, and returns stage/due/overdue totals (`apps/web/lib/queries/applications.ts:222–382,586–650`). Clickable stage and due/overdue views preserve company scope and pagination in their URLs (`apps/web/app/(app)/applications/page.tsx:55–69,117–169`). The mobile application card keeps company, role, stage, vacancy, next step, CV and action in one reading sequence (`apps/web/components/ApplicationsTable.tsx:520–558`); the parent reports no horizontal context/action scroll at 320px. An application date is nullable in the database, a newly generated CV does not pretend it was submitted, and an Applied date is required when genuinely recording that stage (`packages/db/drizzle/0046_application_date_optional.sql`, `apps/web/app/actions/cv.ts:497`, `apps/web/app/actions/applications.ts:28–62,186–216`). The controlled date input removes an untouched local Applied suggestion when the person changes to a later stage, while retaining a date they typed (`apps/web/components/ApplicationsTable.tsx:77–78,123–162`). Existing historical dates are preserved by the migration; the SQL changes nullability only. The dedicated Applications query/action/component suites pass, including cross-page due ordering, ownership, mobile editor and date carry-over. The parent is checking the due-date browser round trip separately. The “Due this week” view includes overdue items by design, so its count overlaps “Overdue”; a first-time comprehension check should confirm that wording is understood.

**J7 — deliberate learning.** Accepting a filter suggestion now takes the same per-account settings lock as a manual edit, reads the latest gate inside the transaction, merges the term and settles the suggestion together (`apps/web/app/actions/learning.ts:137–181`). Concurrent-term and Health integration checks passed in the reliability workstream. The Learning screen already shows calibration only after a minimum decision count and gives bucket denominators (`apps/web/app/(app)/learning/page.tsx:201–224`); that transparency is useful, but it is not evidence of the SPEC's ≥75% agreement after 50 real decisions. Recommendation examples and perceived relevance still need people to assess them.

**J9 — release qualification.** The release workflow checks out the exact successful main CI SHA and runs the evaluation gate with `AVA_EVAL_GATE_REQUIRE_VERIFIED=1` before web and worker identity checks (`.github/workflows/release.yml:18–82`). The ordinary pull-request gate still reports unverified fixtures without failing; its local command passes with an explicit warning. Focused gate/workflow tests pass 16/16 (`scripts/evaluation-report-gate.test.mjs`, `scripts/deploy-config.test.mjs`). The strict command currently exits non-zero because the committed replay at the shipped prompt set is marked unverified. This correctly prevents a *green release identity workflow* from being mistaken for evaluated model quality. As [deployment documentation](../../DEPLOY.md) states, the workflow verifies external deployments; it does not block provider auto-deploy. No current provider keys, delivered alert receipt, full hosted application-and-worker restore or rollback drill were available in this worktree review.

## Remaining acceptance before a 90 claim

1. **J2:** finish the current 25-company diagnostic and the independent frozen 25-company/8-ATS/5-custom-HTML labelled set; verify automatic source choice, zero wrong high-confidence accepts, posting recall/precision and recipe reproduction against SPEC §9. Exercise suspect-empty → failed and homepage-change recoveries in a browser with a person able to name the action to take. A sampled crawl alone cannot lift robustness to 4.5.
2. **J3:** pass the conditional server-undo race regression, then observe a ten-role desktop and phone review with keyboard and screen-reader focus, active-filter comprehension, dismissal correction and retained context. Measure time, errors and whether a second decision can be undone without replacing a previous one.
3. **J6:** complete due-date save/reload and later-stage-with-unknown-date browser round trips; inspect 320px/390px and 200% zoom with long company/role names and an open editor. Check an overdue item beyond the first page, company scope and stage counts after a status change, and comprehension of overlapping due/overdue totals. A viewport change during an unsaved expanded edit remounts the editor; verify that this does not lose entered text before claiming robust responsive editing.
4. **J7:** evaluate ≥50 genuine decisions with high/low bucket denominators and ≥75% agreement in each, and independently review suggested companies and filter explanations. The atomic acceptance regression establishes preservation of intent, not ranking quality.
5. **J9:** produce a current verified provider replay for the shipped prompt set, then prove its release qualification on the exact candidate SHA. Exercise alert delivery to the named operator and a full isolated hosted restore with web and worker plus rollback, measuring the documented 24-hour RPO and four-hour RTO. If provider auto-deploy is meant to be gated, configure that external policy separately; this workflow alone cannot do it.
