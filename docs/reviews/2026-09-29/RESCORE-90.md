## Verification and limits

See [IMPLEMENTATION-VERIFICATION](IMPLEMENTATION-VERIFICATION.md) for exact commands, counts, screenshots and the distinction between local fixtures and live observations.

The first live diagnostic used all 25 committed source labels, serial execution and the production browser fallback, with **no paid AI calls**. It found 17/25 automatically accepted source matches (68%), no wrong automatic **source** accepts, two blocked extraction requests and no independent posting-identity labels. The adapter's “complete” flag did not establish that it found all jobs or only jobs: its samples exposed six policy/help links. The targeted repair removed those six sampled false positives. The final whole-set rerun returned **16/25 automatic source matches (64%)**, zero wrong automatic source accepts, 24 adapter completions and one extraction failure. One further source matched its label but required confirmation. Posting recall and precision remain unmeasured. This **fails** the existing acceptance gate; the sampled precision repair did not establish broad discovery improvement. Neither run is relabelled as full production or human-reviewed acceptance.

No provider credentials were configured in the process or the repository environment files checked for this task. The request for a provider connection and evaluation budget remains unresolved. No current paid-model semantic acceptance was run. The strict release evaluation check intentionally fails on the existing unverified replay. Production provider settings, alert delivery, hosted restoration and human usability/calibration remain unverified in this task.
