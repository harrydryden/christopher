# Browser listing capture audit — 29 September 2026

This audit exercised the production `BrowserRenderer` against three public first-party listings with the existing address and robots guards. The [baseline JSON](implementation-evidence/source-browser-capture-baseline.json) was captured from commit `4a93828` before the changes; the [final JSON](implementation-evidence/source-browser-capture-after.json) contains dated, per-capture counts and machine-extracted public posting URLs from the revised renderer. HTML snapshots and request logs remained in `/tmp` and are not review artefacts. The run made no database, account, notification or paid-model changes.

| Source | Baseline captures / raw HTML retained / unique URLs / renderer state | Final captures / gzip retained / unique URLs / renderer state | Final elapsed |
| --- | --- | --- | --- |
| [Datadog](https://careers.datadoghq.com/all-jobs/) | 20 / 4.06 MB / 190 / incomplete | 42 / 1.02 MB / 414 / control exhausted | 28.2 s |
| [Cloudflare](https://www.cloudflare.com/careers/jobs/) | 9 / 4.31 MB / 225 / incomplete | 18 / 1.05 MB / 402 / control exhausted | 16.4 s |
| [Stripe](https://stripe.com/careers/search) | 13 / 4.74 MB / 153 / incomplete | 63 / 3.86 MB / 662 / control exhausted | 37.7 s |

“Control exhausted” describes guarded browser traversal, **not** independently qualified posting recall. The final Datadog DOM explicitly said “414 jobs available”; 414 distinct posting URLs were extracted. A separate public Greenhouse API observation returned 436 jobs, but its scope is broader than the displayed site listing and is not a valid denominator for this page. Cloudflare has no independently established complete posting set in this audit. Stripe's first and last rendered pages displayed “1 of 63” and “63 of 63”; several location rows can share one posting URL, so 662 distinct URLs must not be compared with a row count. The final JSON preserves exact machine-extracted URLs for later comparison with an independent reference.

The intermediate measurements matter. Compression alone lifted Datadog to 43 captures and 415 URLs in one run, then 43 captures and 384 URLs in another, both marked complete by the old network-idle transition rule. The 415 result was inconsistent and unqualified because its identities were not retained. The 384 result was demonstrably short of the site's displayed 414. Inspection found four captures that advanced pagination while adding no new roles; waiting for unrelated network requests did not prove that the next role slice had arrived. The listing-signature settle then produced 414 Datadog URLs in 42 captures, 402 Cloudflare URLs in 18 captures, and a partial Stripe result at 44 captures/458 URLs because scrolling before every explicit control consumed the deadline. Clicking explicit controls first, while preserving a role-identity settle and using wheel scrolling only when no control is usable, yielded the final results above.

Each browser capture is now bounded by 5 MB decoded HTML, retained captures by 5 MB total gzip data, and traversal by its 60-second render deadline plus 100-step ceiling. The worker decodes one capture at a time and keeps a bounded map of distinct parsed postings; it marks overflow, corrupt captures, failed role transitions and unvisited controls partial. A narrowly scoped count check also marks a browser scan or acceptance observation partial when an Algolia `.ais-Stats-text` field states “N jobs available” and fewer than N distinct roles were extracted. This guards the observed Datadog failure without treating Stripe's repeated location rows as separate jobs. These safeguards do not prove that every source exposes a trustworthy count or that all URL parsing is correct.

[Wise's focused diagnostic](implementation-evidence/wise-browser-partial.json) retained 12 first-page roles and correctly remained partial. The visible “Next pagination page” control navigates to `/jobs?page=2`; [Wise's published robots rules](https://wise.jobs/robots.txt) include `Disallow: /jobs?*`. The guard must not follow that page. A user can still inspect the captured first-page roles, with a clear partial-source state rather than a claim that the board was fully searched.

Validation: core ATS fixtures 97/97, browser fixtures 18/18, capture and acceptance fixtures 19/19, core and worker typechecks, and focused database scans proving that an advertised three jobs versus two captured URLs stays partial, corrupt later captures preserve earlier roles, and a later remote option for the same posting is retained. These are implementation and public-source observations, not a human-reviewed full-site posting qualification or release gate pass.
