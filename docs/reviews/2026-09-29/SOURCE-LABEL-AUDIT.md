# Independent source-label audit for seven unresolved cases

Observed 29 September 2026, approximately 13:20–13:32 UTC. This is a read-only check of first-party careers pages, their outbound links and redirects, and two public board JSON responses. It is independent of AVA's discovery/extraction functions. The compared run is [`live-sources-final.json`](implementation-evidence/live-sources-final.json), generated at 13:10 UTC with a browser renderer and no AI. Its 17/25 source agreements, 0 wrong automatic accepts and 24/25 extraction-complete statuses are **run diagnostics**, not a human-labelled posting-identity acceptance result. In particular, `complete` with zero extracted roles does not prove a genuinely empty employer listing.

Its “View roles” and “View open roles” links lead to [`explore.jobs.netflix.net/careers`](https://explore.jobs.netflix.net/careers). The run's candidate [`netflix.eightfold.ai/careers`](https://netflix.eightfold.ai/careers) redirects to that same `explore.jobs.netflix.net` listing (HTTP 200 after redirect). | **Siemens** | Siemens' first-party [`en-gb/company/jobs/`](https://www.siemens.com/en-gb/company/jobs/) contains an “Explore all jobs” anchor to [`jobs.siemens.com/en_US/externaljobs`](https://jobs.siemens.com/en_US/externaljobs). That portal's “All Jobs” anchor leads to [`/SearchJobs/`](https://jobs.siemens.com/en_US/externaljobs/SearchJobs/). The text-only web reader returned 406 for the portal, so this portion was independently inspected from the public HTML response. | Manifest's SearchJobs listing is supported. Discovery proposed the Siemens UK company-jobs landing page at confirmation confidence and extracted zero. This is **landing-page/incomplete**; the linked portal is demonstrably nonempty at inspection time. |
| **Spotify** | First-party [`Start your journey`](https://www.lifeatspotify.com/start-your-journey) navigation links “All Jobs” to [`lifeatspotify.com/jobs`](https://www.lifeatspotify.com/jobs). The zero in the static, apparently filtered/loading page is **not a known global empty state**. There is no first-party evidence here that the old Lever *board* should replace the first-party all-jobs URL. |
| **Zapier** | First-party [`zapier.com/jobs`](https://zapier.com/jobs) explicitly says it is hiring and links “View job openings” to its job-board section. Its public HTML embeds a `JobBoard` configured with `useAshbyData: true`; the unhydrated text response omits posting links. A direct public [Ashby board JSON](https://api.ashbyhq.com/posting-api/job-board/zapier) returned 10 listed unique IDs and exact `jobUrl` values at 13:29:20 UTC, including [Finance Manager, Marketing](https://jobs.ashbyhq.com/zapier/cb1aec2c-05cd-4598-8117-bd1f7ed9a49f). | Discovery selected the *labelled URL* `/jobs`, but extraction claimed complete with zero. This is the clearest **false-complete empty extraction** in the seven cases. The first-party page's embedded board configuration and live API list make “zero open roles” untenable at inspection time. |

The labels themselves should remain unchanged pending a named reviewer. Netflix especially needs a decision on whether the expected source is the first-party landing URL, the redirected board URL, or an allowed alias pair. Salesforce's old host is a valid redirect alias; matching should distinguish that from a different destination such as an APAC locations page. Datadog, Cloudflare, Siemens and Zapier demonstrate why source selection and extraction completeness must be scored separately. No row above establishes full-site recall or precision.

## Independent machine posting snapshots

[`posting-references.json`](implementation-evidence/source-audit/posting-references.json) wraps two separately fetched public API snapshots for optional diagnostic comparison. [`zapier-ashby.snapshot.json`](implementation-evidence/source-audit/zapier-ashby.snapshot.json) lists 10 `isListed=true` Ashby IDs and URLs; [`datadog-greenhouse.snapshot.json`](implementation-evidence/source-audit/datadog-greenhouse.snapshot.json) lists 436 Greenhouse IDs and first-party detail URLs. The original public JSON responses are retained as [`zapier-ashby.raw.json`](implementation-evidence/source-audit/zapier-ashby.raw.json) and [`datadog-greenhouse.raw.json`](implementation-evidence/source-audit/datadog-greenhouse.raw.json). Each reference records the UTC response `Date`, source URL, raw SHA-256, direct unauthenticated enumeration method and exact returned posting URLs. Their `reviewStatus` is `machine_enumerated` and `completeScope` is `false`: neither is an independently human-reviewed posting golden set or eligible to satisfy the release gate.

The Zapier raw response SHA-256 is `9219a038de991448cf8a1a0e75489752e21a5e38067495cdc00fb9662098a5c9`; Datadog's is `8ded3d1e58d0f2e6141ea7c4072bf7290875ef2b7258c2307c51fec74ec1fc1c`. URLs and counts are time-bound. Greenhouse/Ashby publication and first-party presentation may differ, and no human checked every posting against the visible site. The remaining five cases have source/navigation evidence only, not an exhaustive job-ID snapshot.

## Orchestration review of the Netflix source label

After this audit, Astra independently reopened the official [careers homepage](https://jobs.netflix.com/), its [View roles destination](https://explore.jobs.netflix.net/careers), and the [Eightfold alias](https://netflix.eightfold.ai/careers). The link and redirect agree. The current manifest therefore corrects Netflix to the recognised Eightfold alias and records the company-owned destination as an equivalent URL, dated 29 September. This supersedes the earlier pending-adjudication recommendation for **source identity only**. It is an independently checked URL correction, not a human posting review or a code-performance improvement; no historical observation is rewritten. The homepage robots restriction and low-confidence discovery outcome remain real limitations.
