The user-visible consequence is material. `scanHtmlSourceContinued` can form positive postings from staged pages, but `handleScanCompany` returns `TaskDeferred` on `continueAt` before `commitScan`; thus the 1,774 currently verified URLs are not visible as jobs. Simply dropping that early return would collide with scan task/source idempotency and checkpoint cleanup. A bounded next design should introduce an explicit **non-terminal positive-only publication** path: atomically advance a durable published-page cursor with the inserted/updated posting identities under source ownership and fingerprint checks; include pages already staged by an interrupted claim; label the source and jobs as partial; preserve first-scan seeded semantics; never infer absence, increment missing counts or close jobs from this path. The normal complete scan remains responsible for closure and full recall. Existing `reconcile(..., mode: "partial")` permits positive sightings without absence-based closures, but the current worker commit path must be made safe for repeated chunks before using it. A changed source fingerprint, generation restart, expired generation or ownership loss must not silently combine observations from different listing generations. This is a proposal, not an implemented or qualified result.
