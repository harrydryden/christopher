# Enlarged text and keyboard audit, 29 September 2026

This is a technical browser check on a disposable local application at `127.0.0.1:3137`, with demo and unverified-member accounts in `ava_review`. No provider calls or production data were used. It is not a human usability study, a screen-reader test, or a native browser zoom certification.

I tested a 1280 × 800 viewport and, for the table breakpoint, a 1440 × 800 viewport. To exercise text reflow, a browser script doubled each rendered element's computed font size, including fixed-pixel text. I reapplied it after React created decision and conflict panels, then checked those controls' computed sizes. This is **text-only enlargement emulation**: browser zoom shortcuts did not change the headless browser's CSS viewport, and CDP page scale would not establish text reflow. Viewport resizing and native page zoom are distinct tests.

At normal 1280px desktop width, Roles and Library employment remain tables (their content widths were 1040px). At 200% text enlargement, both become cards and have no page-wide horizontal overflow at 1280px, 1440px or 1600px. The responsive threshold is `60em` of the table's own container, so it scales with enlarged text and available content width without duplicating any form controls.

The audit does not establish native browser zoom, keyboard access to every screen state, assistive-technology announcements, or real-user comprehension. The conflict was created with a disposable saved library and a concurrent version in the local database; no external write was made.
