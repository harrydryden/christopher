# First-use and Health recovery audit — synthetic fixture

This is a bounded browser/code audit of the first company check. It uses an isolated `ava_firstuse_audit` database cloned from the mocked 25-page listing fixture in the adjacent [partial-publication evidence](../partial-publication/). No production data, external page, worker daemon, paid AI call or email was involved. The existing authenticated test session stayed in `/tmp`.

The browser blocked non-local requests and recorded zero attempted external requests and zero page errors in all five states. At 375px, Roles and Health had no horizontal document overflow. The text-enlargement check first captured every element's computed font size, then set each to exactly twice its original value; sampled Roles setup text changed from 14 to 28px and Health text changed from 13 to 26px (queued/complete) or 14 to 28px (interrupted), with document width remaining 375px. These scripted checks do not establish compatibility with a screen reader or represent user research.

## Concrete findings

1. **Fixed:** The Health `incomplete_read` detail said “This read did not publish roles” even when the same page and Roles showed 25 published matches. It now states that the listing did not finish and that any matching roles already found remain available. The sentence also remains truthful at zero published pages. The focused query test passed 2/2 and web typecheck passed.
2. **Fixed:** The queued/offline first-check path led to Companies with the wrong “Discovery queued” label and no stopped-worker instruction. Pending setup now reads worker status, explains stopped or restarting monitoring, and links to Health. The first-scan step also points to Health; its completion still requires a complete successful scan. The Companies row distinguishes discovery from scanning, with deterministic priority if both task types exist.
3. **Fixed:** A running task with a stopped worker gave false “Scanning…”/“Refreshing…” cues. Companies now qualifies the status and links to Health; the disabled menu control names monitoring as the wait. The worker read on Companies occurs only when a visible row has a running task. Setup reads worker status only when there is queued or running company work, including a later rescan after first-scan completion.

The original queued/offline browser capture was inspected before edits, but the script overwrote that JSON and screenshot on its fixed rerun. The pre-fix wording and route are recorded above as an observation, not attributed to the fixed capture. The separate running/offline before-and-after captures remain available. Five focused web files passed 44/44 tests ([log](focused-tests.log)); web typecheck passed ([log](typecheck.log)).
