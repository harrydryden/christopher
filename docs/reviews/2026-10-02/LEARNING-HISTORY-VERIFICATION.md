# Learning history and profile comparison — 2 October 2026

This checkpoint follows `81c63cb`. Astra integrated the journeys and verified the browser behaviour; Sol implemented the two workstreams and independently reviewed them. It closes the local Learning history gaps identified in the preceding Health acceptance audit against SPEC R-6.2 and R-6.4.

Reason tags now have newer/older navigation through all standing decisions, 20 per page. Reads and counts are account-scoped, ties have a deterministic ID order, and page input is validated before applying a bounded offset. A valid page beyond the end clamps to the last page; malformed, duplicate or numerically unsafe input returns to the first page. Superseded decisions remain excluded. Dirty and pending editors stay mounted outside the selected page, retain their expected saved state and offer explicit discard. Profile-version context is preserved in page links. An off-page successful save names the role and focuses its confirmation.

Saved preference profiles now have a keyboard-operable comparison with the previous owned version, even where version numbers have gaps. It shows labelled additions/removals for profile text, pinned statements and questions/answers, including statement boundaries and question-record changes. Text is escaped rather than interpreted as markup. The comparison algorithm uses bounded lookahead; unusually fragmented changes have a compact view plus complete before/after text. Normal comparison opens in place. Viewing a different stored version opens an explicitly labelled new tab, preserving unsaved current profile and pin edits. Malformed or unavailable versions have an honest unavailable state and a route back to the current profile; they never reveal another account's version.
