Two J7 gaps remain and can be implemented separately:

1. **Reach older standing reason tags.** `getReasonTagEditor` in `apps/web/lib/queries/learning.ts` currently returns only the newest 20 standing decisions; `ReasonTagList` is the only tag-editing UI. Add bounded 20-row page navigation on Learning with an account-scoped count and a deterministic `(createdAt DESC, id DESC)` order. Validate and clamp the page parameter, include a route back to newer rows, and preserve the profile-history query parameter when paging. Keep one `ReasonTagList` at the same tree position and feed it the selected page; its keyed rows and retained dirty/pending union must survive page changes. Update the outside-page wording and the saved notice accordingly. Do not weaken `saveDecisionTagsSetting`'s standing-decision and expected-tag guard. Tests: a member can reach and save decision 21; another account's row is absent; an edited or pending row stays mounted across page navigation and a sibling refresh; stale refusal preserves its guard; an out-of-range page recovers to a valid page. A real browser page transition is needed because a component-prop test alone cannot prove that navigation preserves client state.

2. **Compare stored profile versions.** The current selector in `apps/web/app/(app)/learning/page.tsx` displays one stored version, but SPEC R-6.4 says versions are diffable. Add a read-only “Compare with previous version” control beside the existing selector, available whenever the viewed version has a predecessor. Fetch exactly that predecessor with `getPreferenceProfile(user.id, previousVersion)`, using the account-scoped version list to choose it; never accept an arbitrary profile ID. Present a labelled, accessible line-level markdown diff with additions and removals, escaping content as React text, and a clear no-changes state. Keep this comparison inside the existing profile card so current profile/pin/question editors remain mounted and their dirty text plus version guards are untouched. Tests: two versions show a change; identical versions say so; a single version has no comparison control; invalid or foreign version parameters reveal nothing; toggling comparison while a current editor is dirty retains its text and submitted guard. A browser replay should check keyboard, phone reflow and same-route navigation.

Implementation ownership can be separated: one worker owns the reason-tag query/list/navigation and its tests; another owns a profile-comparison component/query and its tests. Both need a small insertion in `learning/page.tsx`, so integrate those page edits sequentially. Neither path requires changing the existing write actions or adding a model call.
