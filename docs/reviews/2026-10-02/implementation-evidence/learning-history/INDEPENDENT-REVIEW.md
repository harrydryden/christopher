# Independent Learning history review

Reviewed the J7 Learning history changes on 2 October 2026 against SPEC R-6.2 and R-6.4. I found no blocking source defect in the frozen candidate. These checks improve access to stored decisions and explain stored profile changes; they do not establish learning or recommendation quality.

Reason tags now have bounded pages of 20 standing decisions. The query scopes both count and rows to the signed-in account, orders by creation time and ID, rejects malformed or duplicate query values, and clamps a requested page before constructing its SQL offset. The existing `ReasonTagList` keeps keyed dirty and pending editors mounted when a decision leaves the server page; the action still compares the original tag snapshot before changing a standing decision. [Focused tag query and component tests](tag-focused-tests.txt) passed 8/8. The [full web suite](full-web-tests.txt) passed 1,379 tests across 154 files.

The browser reached decisions 21–26 on page 2 while preserving an edited page-1 row, its selection and original guard, plus unsaved profile and pin text ([navigation](dirty-older-navigation.txt)). Saving a page-2 decision changed the intended [database row](older-save-db.txt). The pending case was exercised separately: an account advisory lock held a tag save in flight; clicking Newer left page 2 visible with “Saving…” and the selected tags ([pending](pending-newer-navigation.txt)). The hold exceeded the database statement timeout. Once the action settled, the queued navigation reached page 1 with the outside-page row retained and an uncertain-outcome alert ([released state](pending-save-released.txt)); [the database](pending-save-db.txt) still had the old tags. Retrying from that retained row then saved the intended tags, removed the row from the page-1 view and focused a named success notice ([browser](retained-retry-success.txt), [database](retained-retry-db.txt)). This proves pending navigation and failure recovery under a timeout, **not** a successful in-flight save across navigation.

The profile card compares a selected stored version with its nearest earlier owned version. Invalid, absent or foreign version parameters do not fall back to another profile. The read-only disclosure labels line changes in markdown, pinned-statement boundaries and open questions/answers; it notes question-record identity changes without exposing opaque IDs. Its lookahead and compact output are bounded, and a large abbreviated comparison still exposes both complete section texts. The historical-version selector opens a native new tab, leaving edits in the current tab mounted. [Profile comparison tests](../learning-completion/profile-comparison-tests.txt) passed 6/6; the combined page, comparison and tag checks passed 23/23 on independent rerun. A keyboard browser replay opened the comparison without changing unsaved profile/pin text or the profile guard ([comparison](comparison-keyboard-drafts.txt)). The historical page opened separately ([new tab](historical-tab.txt)) and the [original tab](original-tab-drafts.txt) retained both drafts. The [375-pixel comparison](comparison-phone.png) was inspected without horizontal overflow.

The browser and database fixtures are local and synthetic. They do not supply the 50 genuine decisions, calibrated bucket agreement, independent recommendation review or representative usability required to raise J7 readiness. Scores remain unchanged on the full-job rubric.
