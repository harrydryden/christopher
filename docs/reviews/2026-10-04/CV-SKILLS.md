# CV skills selection and presentation

CV review supports up to ten individual skills per section. The counter and Add controls expose the limit before submission. Save and preview also validate the limit. Editing older bullet-based skill sections converts them to structured skill items, avoiding the six-bullet validation error. Existing stored drafts and Library evidence remain readable at their original capacity.

The review editor offers sections and individual skills from the Library snapshot saved with the CV. The UI explains that snapshot boundary. Labels are copied exactly; these are direct edits, not new claims of verified evidence. The section picker copies the first ten labels, and users can remove or replace them before saving.

New builds allocate skill sections only when relevant to the job. Structured skill selection uses the planner's exact skill-source references, allowing semantic matches without admitting every skill in the same Library block. The fitting stage filters out unrelated items even when there is spare page space. Older builds without a semantic plan fall back to explicit text relevance. Source Library entries remain unchanged.

PDFs retain the Skills group heading and show named skill sections beneath it. Pills use smaller type, padding and gaps; section spacing is reduced. Rendering and page measurement use the same layout. A regression fixture with three named sections and thirty realistic mixed-length labels fits within half an A4 page including headings. This is a representative layout guarantee, not a promise for an unlimited number of sections or arbitrarily long headings.

Verification includes schema/fitting regressions, editor limit tests, browser preview at ten skills, adding from Library, and visual inspection of the rendered thirty-skill fixture. Model-facing prompts are covered by the prompt registry; deterministic tests do not substitute for a live AI quality evaluation.
